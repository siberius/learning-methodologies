# Використання та встановлення

## Оберіть правильну точку входу

Використовуйте цей скіл для створення нового освітнього застосунку, суттєвої зміни його дидактичної структури або методичного аудиту наявного дизайну. Звичайна косметична правка інтерфейсу чи виправлення дрібної технічної помилки не потребують повної дидактичної перебудови.

Надайте відомі вам дані про учнів, освітню мету, контекст і практичні обмеження. Агент повинен спиратися на надану інформацію та запитувати лише про критичні прогалини в контексті або відкриті методичні рішення. Він не повинен проводити обов'язкове шаблонне інтерв'ю про аудиторію та тон спілкування чи вимагати окремого погодження для звичайних технічних рішень, які вже випливають із вашого завдання.

## Супровід рішень під час створення

Коли постає новий важливий вибір, скіл пропонує кілька доречних навчальних варіантів: коротке пояснення простою мовою, конкретний приклад у поточному проєкті та рекомендацію. Він запам'ятовує ваші рішення та переносить їх у код і процедури перевірки. Ви можете сказати «обери звичайні рішення за мене», щоб делегувати рутину, або знову попросити порівняти варіанти. Невеликі офлайн-активності залишаються простими. Цей процес підтримують картки методів, настанови з когнітивного інтерфейсу та алгоритми адаптивної практики за потреби.

## Встановлення через skills.sh CLI

Встановіть україномовну версію за допомогою [Skills CLI](https://github.com/vercel-labs/skills). Прапорець `-g` означає встановлення для поточного користувача глобально; `-a codex` обирає агент Codex. Замініть його на `-a claude-code` для Claude Code або пропустіть цей параметр, щоб обрати агент інтерактивно:

```bash
npx skills add siberius/learning-methodologies --skill metodyky-navchannya --full-depth -g -a codex
```

Без параметра `--agent` команда `skills use` виводить підготовлений системний запит. Для тимчасового запуску підтримуваного агента зі скілом виконайте:

```bash
npx skills use siberius/learning-methodologies --skill metodyky-navchannya --full-depth --agent codex
```

## Нативний пакет скіла

Зберігайте файли `SKILL.md`, `LICENSE` та папку `references/` в одному каталозі скіла з назвою `metodyky-navchannya`. Використовуйте механізм встановлення скілів, передбачений вашим клієнтом. Сама по собі наявність Markdown-файлу на диску не гарантує його автоматичного виявлення.

Для клієнтів, що використовують шлях `~/.agents/skills`, типова структура каталогу:

```text
~/.agents/skills/metodyky-navchannya/
  SKILL.md
  references/
  LICENSE
```

Для Claude Code відповідною директорією зазвичай є `~/.claude/skills/metodyky-navchannya/`. Зберігайте наявні файли користувача; перевіряйте відсутність конфліктів перед копіюванням. Переконайтеся у виявленні скіла у вашому робочому клієнті. Не вважайте сам факт встановлення доказом того, що агент дійсно використав настанови скіла.

## Автономний Markdown

Передайте агенту, здатному слідувати інструкціям, згенерований єдиний файл `metodyky-navchannya.md` і прямо попросіть його використовувати цей документ для виконання завдання. Він містить усі умовні довідники як вбудовані розділи та не має зовнішніх файлових залежностей. Цей шлях завантажує більше тексту одразу, проте потребує лише одного файлу інструкцій.

Назви моделей не є механізмами встановлення скіла. Сумісність залежить від здатності хост-застосунку зчитувати інструкції Markdown, підтримуваних інструментів і прав доступу.

## Робота відповідно до дидактичної потреби

| Потреба | Відповідний довідник |
|---|---|
| Режими тьютора, неперервність навчання та контрольні точки | `references/tutor-state.md` |
| Чому метод підходить і як він змінює поведінку застосунку | `references/didactic-rationale.md` |
| Загальне проєктування, аналіз або межі завдань | Основний документ `SKILL.md` |
| Логіка допомоги, альтернативні відповіді чи вимоги навчальних програм | `references/decision-examples.md` |
| Вибір методів, рівні підтримки чи правила просування | `references/methods.md` |
| Бали, рубрики оцінювання, адаптивність або докази навчання | `references/assessment.md` |
| Наукова модель, фізичний експеримент чи рольова гра | `references/simulations.md` |
| Використання сервісів ШІ в готовому продукті | `references/runtime-ai.md` |
| Вибір моделі, рівні міркувань, швидкість або адаптація середовища | `references/model-profiles.md` |
| Рішення автора та неперервність дидактичного діалогу | `references/design-dialogue.md` |
| Форми подання інформації, мультимедіа та керування увагою | `references/cognitive-ux.md` |
| Планування інтервалів повторення та підбір складності | `references/adaptive-practice.md` |
| Ігрові механіки, мотивація та перенесення знань | `references/learning-games.md` |

Не завантажуйте всі довідкові файли автоматично в нативному режимі. Звичайна офлайн-вікторина здатна надавати пояснення та підказки без виклику хмарного ШІ. Демонстрація вчителя біля дошки потребує вдалих запитань для бесіди, а не складного журналу обліку користувачів. Залучайте одну чи кілька експертних точок зору відповідно до завдання, не запускаючи автоматично цілу команду агентів.

## Підтримка та збирання видань

Основними вихідними файлами є `SKILL.md` та умовні матеріали в папці `references/`. Автономний файл `metodyky-navchannya.md` є згенерованим дистрибутивним артефактом. У репозиторії розробника перезібрати та перевірити його можна за допомогою команд:

```sh
python3 testing/build_portable.py --edition uk
python3 testing/build_portable.py --edition uk --check
python3 testing/check_package.py
```
