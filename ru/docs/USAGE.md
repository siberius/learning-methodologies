# Использование и установка

## Выбери подходящую точку входа

Используй скилл для нового образовательного приложения, существенного изменения его учебного устройства или анализа этого устройства. Косметическая правка или обычное исправление ошибки не требует переработки обучения.

Предоставь известные сведения об обучающихся, цели, контексте и практических ограничениях. Агент должен использовать существующие данные и спрашивать о существенных пробелах контекста и открытых учебных решениях. Он не должен повторять фиксированное интервью об аудитории и тоне или запрашивать разрешение на обычные проектные решения, уже охваченные заданием.

## Сопровождение решений при создании

При новом существенном выборе навык предлагает несколько подходящих учебных вариантов: краткое объяснение, конкретный пример и рекомендацию. Он помнит решения и связывает их с реализацией и проверкой. Скажи «обычные решения выбери за меня» для делегирования или снова попроси сравнить варианты. Небольшие офлайн-задания сохраняют свой масштаб. Процесс поддерживают карточки методов, когнитивный интерфейс и необязательная адаптивная практика.

## Установка через Skills CLI

Выбери языковую версию через [Skills CLI](https://github.com/vercel-labs/skills). `-g` означает установку для пользователя, `-a codex` выбирает Codex. Для Claude Code используй `-a claude-code` или пропусти параметр для интерактивного выбора. Устанавливай только используемые версии.

```bash
npx skills add siberius/learning-methodologies --skill metodiki-obucheniya --full-depth -g -a codex
```

Без `--agent` команда `skills use` выводит подготовленный запрос. Для временного запуска поддерживаемого агента с навыком:

```bash
npx skills use siberius/learning-methodologies --skill metodiki-obucheniya --full-depth --agent codex
```

## Нативный пакет скилла

Храни `SKILL.md`, `LICENSE` и `references/` в одной папке скилла, обычно с именем `metodiki-obucheniya`. Используй поддерживаемый клиентом механизм установки. Наличие Markdown-файла где-то на диске само по себе не гарантирует автоматического обнаружения.

Для клиентов, использующих `~/.agents/skills`, возможен такой путь:

```text
~/.agents/skills/metodiki-obucheniya/
  SKILL.md
  references/
  LICENSE
```

Для Claude Code соответствующая папка обычно `~/.claude/skills/metodiki-obucheniya/`. Сохраняй существующие пользовательские файлы; до установки проверь конфликты. Подтверди обнаружение в фактическом клиенте. Не считай установку доказательством использования скилла агентом.

## Автономный Markdown

Передай агенту, способному следовать инструкциям, сгенерированный `metodiki-obucheniya.md` и явно попроси использовать файл для задачи. Он содержит условные справочники как встроенные разделы и не зависит от относительных файлов. Этот путь загружает больше текста сразу, но требует одного файла инструкций.

Названия моделей не являются механизмами установки. Совместимость зависит от способности приложения-среды загрузить Markdown-инструкции и следовать им, от инструментов и разрешений.

## Работай по необходимости

| Потребность | Соответствующее руководство |
|---|---|
| Режимы тьютора, возобновление и контрольные точки | `references/tutor-state.md` |
| Общее проектирование, анализ или границы | Ядро в `SKILL.md` |
| Неоднозначная помощь, альтернативные ответы или заявления о программе | `references/decision-examples.md` |
| Выбор методов, помощь или продвижение | `references/methods.md` |
| Баллы, рубрики, адаптивность или свидетельства обучения | `references/assessment.md` |
| Научная модель, эксперимент или ролевая игра | `references/simulations.md` |
| ИИ-сервис в готовом приложении | `references/runtime-ai.md` |
| Модель, глубина рассуждения, скорость или адаптация клиента | `references/model-profiles.md` |
| Выбор автора и сохранение решений | `references/design-dialogue.md` |
| Представления, мультимедиа и внимание | `references/cognitive-ux.md` |
| Расписание повторения и сложность | `references/adaptive-practice.md` |
| Механики, мотивация и перенос | `references/learning-games.md` |

Не загружай автоматически все справочники в нативном режиме. Офлайн-викторина может давать обратную связь и подсказки без ИИ во время работы. Демонстрации преподавателя могут быть нужны вопросы для обсуждения, а не индивидуальные записи. Используй один или несколько экспертных взглядов по задаче без автоматического запуска нескольких агентов.

## Поддерживай версии

Авторские исходники находятся в `SKILL.md` и условных справочниках. Автономный файл является генерируемым дистрибутивом. В рабочей копии сопровождающего пересобери его из корня репозитория:

```sh
python3 testing/build_portable.py --edition ru
python3 testing/build_portable.py --edition ru --check
python3 testing/build_portable.py --edition all --check
```

Генератор находится в локальных игнорируемых инструментах разработки. Пользователи дистрибутива могут применять любую готовую форму, не запуская его. Он встраивает справочники с уникальными якорями, поэтому повторяющиеся заголовки остаются однозначными.

Согласуй README и примеры преподавателя с ядром. Сохраняй автора, версию, происхождение и лицензию MIT. Для другого агента регистрируй поддерживаемый пакет вместо отдельной редактируемой копии. [Чешская версия](../../cs/README.md) сохраняет общие принципы и добавляет условное местное руководство. Генерируй её с `--edition cs`, все версии с `--edition all`. При изменении общего принципа проверяй последствия для языковых версий; не навязывай автоматически чешские требования программы международным проектам.

## Анализируй результат

Проверяй целевое действие и свидетельства, предметную правильность, обратную связь, помощь, доступность и эксплуатационные ограничения, значимые для приложения. Различай техническое поведение, дидактическую пригодность и реальные результаты обучения. Указывай, что проверено и что остаётся неизвестным.

Опубликованный [протокол оценки моделей из восьми задач](MODEL-EVALUATION.md) предоставляет сопоставимые задачи и критерии оценивания. Не включай критерии во вход испытываемой модели. Набор подготовлен, но не выполнен; прежние исследовательские прогоны не устанавливают межплатформенную надёжность. Сообщай только о реально проведённых оценках, отделяя исходные результаты от исправленных.

Выбирай по сложности задачи до названия модели. Если после целевого исправления содержательный критерий всё ещё не выполнен, следуй правилам усиления и остановки в справочнике моделей. Отсутствующие источники или инструменты не исправляются большей глубиной. Стандартная скорость обслуживания является начальной; платное ускорение представляет отдельный разрешённый выбор.

При выборе метода для разработки приложений читай [дидактическое обоснование](../references/didactic-rationale.md). Оно объясняет, как метод меняет действия учащегося и обратную связь; это не доказательство эффективности готового приложения.
